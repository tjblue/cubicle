Configuration reference

Start small · defaults

The smallest profile is {"name": "My space"}; it opens one terminal. Add "panes": ["terminal", "browser", "files"] to open tools side by side. Use root for the space folder. Each pane can instead be an object, such as {"type": "browser", "url": "https://example.com"} or {"type": "terminal", "command": "npm run dev"}. Omitted settings use app defaults. The short form gives each tool its own equally sized pane.

Space defaults & launch behavior

name, description, space.name, space.root and space.color define profile and space defaults in the detailed form. In the short form, the profile name is also the space name. Paths can use ${workspace} and ${home}. Existing-space launches can replace the layout or add pane groups; replacement is confirmed first.

Layout & pane groups

layout is a tree: for advanced layouts, a split has direction (row or column), children, and optional relative sizes. A group contains tabs and an active tab ID. Nest splits to create more complex layouts; tabs in one group share a pane.

Terminal tabs

Set shell, cwd, env, startupCommand, and title. Commands are proposed launch actions, not run by this mockup. A real implementation should surface commands before execution and handle missing shells or paths.

Browser tabs & favorites

Set url and favorites as name/URL pairs. Favorites belong to their browser tab in this proposal. A browser tab can start on a different URL from its favorites.

Files & pinned locations

Set a Files tab's root, pins (name/path pairs), and reveal path. Paths are launch targets, not files read by this prototype.

Persistence & scope

Profiles and simulated spaces are stored in this browser's local storage. Import/export uses JSON files. This mockup does not open terminals, browse files, or change real spaces. YAML could be added later as another serialization of the same model.
